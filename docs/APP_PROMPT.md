# Oasis project brief

Build **Oasis**, a personal native macOS browser in Swift and SwiftUI, using system WebKit to render websites. Target macOS 26 or later and use real Apple Liquid Glass APIs.

Create a traditional, dependable browser with a clean red visual identity. Use a **sidebar containing only tabs**: compact single-line items with the page favicon and document title, selection, loading indicators, pinned tabs, close actions, reordering, and a new-tab button. Omit a Tabs heading and tab count. Keep history, bookmarks, and the reading list in separate panels opened from the app menus or page-actions menu.

Replace the start page with an empty transparent `about:blank` canvas. Name blank tabs “Empty Tab.” Only when the user presses the toolbar plus button or ⌘T, present a dismissible floating Liquid Glass search capsule inspired by Siri’s large input and subtle luminous edges, using red, pink, and warm orange accents. Offer local autocomplete from bookmarks, recent history, and common site names without replacing the typed query or navigating automatically. Highlight the first autocomplete suggestion by default and make Return open it; arrows choose other results and a click opens the clicked result. Typing alone must never navigate or replace the query. If no suggestions match, Return uses the exact input. Opening the search popup must not create or select an empty tab. Keep the current webpage in place behind it, and create a new tab only when a search or explicitly selected suggestion is submitted. Dismissing the popup must leave the tab list unchanged. Center the popup horizontally in the full window, counting the sidebar, and position it around the upper third. Animate its appearance as a larger, softly blurred surface sliding back into its resting size. Keep the input stationary as suggestions appear beneath it. Smooth visual typing feedback and suggestion transitions without delaying actual input, caret behavior, completion selection, or submission. Use neutral, scene-adaptive selection highlights rather than prominent red fills, and layer it over all browser chrome and the sidebar. Escape or clicking outside dismisses it. Selecting/restoring blank tabs and ⌘L must not open the popup; ⌘L focuses the normal address field. Put matching icon-only plus and refresh glass buttons next to the sidebar toggle, and remove the sidebar’s new-tab button.

Make the window translucent and the browser controls feel suspended above the webpage. Use a rounded capsule address and search field, compact glass navigation buttons, and floating page actions. Let content extend behind the controls while keeping fixed website headers and important interactive content below their obscured area. Render websites with their original CSS and colors. Do not inject styles or recolor pages. Center the capsule address field between balanced controls and center the URL text inside it. Match the native top bar to WebKit’s derived page background color and keep the sidebar’s existing translucent tint on colored pages, falling back to its untinted empty-window appearance on white and near-white pages without changing webpage HTML or CSS. Make every button’s whole visible surface clickable. Make the full URL capsule activate editing without selecting the address automatically on clicks or ⌘L. Preserve native caret placement, selection, clipboard shortcuts, and input-method composition on subsequent edits. Disable global background window dragging and use explicit drag regions in the empty top bar and sidebar top strip so controls and text selection receive their own mouse events. Provide regular address-bar autocomplete on empty windows and loaded pages, with site/history/bookmark matches, direct navigation/search actions, arrow-key selection, Return to open, and normal Tab focus navigation. Use a neutral, adaptive icon for page actions, and make the whole glass menu button open the menu. Respect Reduce Transparency and keyboard accessibility.

Pass the system appearance to Google through native WebKit so its device-default theme follows macOS, without injecting styles or overriding a theme explicitly saved by the site.

Start new windows with zero tabs and return to that state after the last tab closes. Navigating from an empty window creates its first tab. Make session restoration opt-in.

Implement real browsing features: URL and search handling, multiple tabs and windows, back/forward/reload/stop, persistent searchable history, bookmarks and favorites, a reading list, downloads with progress and cancellation, file uploads, website dialogs, camera and microphone permission prompts, private windows with isolated in-memory website data, normal-session restoration, reopening closed tabs, find on page, zoom, reading mode, printing, PDF export, web archives, bookmark HTML import/export, settings, and common macOS shortcuts.

Use SwiftUI for the interface and narrow AppKit bridges only for system functions and WebKit hosting. Keep browser state separate from reusable views. Persist user data locally and atomically, preserve a damaged library rather than overwriting it, and never bypass TLS certificate validation. Clearly document the supported feature set and features that require further work, such as extensions, credential autofill, and cloud synchronization.

Deliver a runnable `.app`, source code, build/run instructions, and meaningful checks of URL handling, persistence, private browsing, and preservation of original website styling. Inspect the actual native interface before handing it over.

Add an off-by-default, persistent Spoof Mode toggle with a full-hit-area mask button beside Downloads, also available in page actions and Privacy settings. Indicate enabled state with a filled icon and neutral highlight. Reconcile the current preference across navigation and cached-page restoration, repair accessors idempotently, and suppress covered synthetic events as well as native events without stacking listeners or silencing unrelated console logs. Suppress page-visible visibility, window-focus, and mouse/pointer boundary events, report a stable visible/focused state, and preserve genuine input and form focus. Use document-start injection in all frames and reversible patches. Do not generate artificial user activity or modify website CSS/HTML. Apply live changes where accessible, require reloading for full early/frame coverage, and accurately document that this cannot conceal all activity signals.
